# Existing and planned state foundations

The editor's first renovation journey needs to distinguish what is present from what should
exist afterwards without pulling the whole execution and as-built lifecycle into MVP. This
feature owns that minimum domain seam: separate canonical Existing and Planned records, stable
links to their spatial subject and optional source relationship, and a derived comparison.

It does not move in-progress, installed or as-built capture into MVP. Those remain under
[[Object states]], [[State visualization]] and [[As-built documentation]] for later delivery.
Nor does it turn Existing or Planned into a canvas layer or reuse a work-progress status.

## Outcome

A spatial object can describe its current and intended state independently, and downstream work
can refer to the intended outcome without either state overwriting the other.
