# Competitive patterns for the next editor usability increment

Research date: 2026-09-13. Scope: approachable 2D plan drawing and editing. This is primary-source desk research, not a hands-on competitor audit or a usability study. No competitor account was created and no live editing task was performed. Findings distinguish documented interaction behavior (D), marketing positioning (M), and our design inference (I).

## Decision this evidence supports

Prioritize making existing drawing, selection and precision routes easier to discover and understand. The strongest transferable pattern is a short path from an approximate shape to an exact, reversible edit. Competitor breadth is not a reason to add geometry types, 3D, AI, catalogues or CAD commands.

Our [current editor guide](../../../using-plan-editor.md) already documents three empty-floor starts, Add, rectangular/free-form Rooms, inline dimensions, numeric controls, hosted openings, Alt overlap cycling, a keyboard-selectable floor list, reference calibration, Undo/Redo and narrow-layout Details/Layers rails. These are existing capabilities, not a competitor-derived feature backlog. Whether users find and understand them remains a hypothesis for the local audit and user validation.

## Patterns to adapt within current capability

1. **Make the first useful action evident.** Keep the existing Room/reference/empty starts and make the next action match the chosen route. I: room-first documentation suggests a useful default, not proof that every homeowner should start with a Room. Do not add a template library or auto-created geometry solely because competitors have them.
2. **Expose precision at the point of uncertainty.** The user should recognize that an existing dimension is editable and know what moves before applying it. I: evaluate the discoverability of current labels and Details routes; retain existing independent Room/wall semantics and wall Preview → Apply. Competitor wall-generated rooms do not justify changing our domain model.
3. **Use a short, state-specific instruction.** Explain the current gesture, next step, Finish/Cancel and available numeric alternative where drawing happens. I: prefer this to importing a general product tour. The Planner 5D tour is documented, but its furniture/3D sequence does not match this increment's purpose.
4. **Offer an understandable route through overlaps.** Sweet Home 3D's named item submenu is a concrete pattern for disambiguation. I: first check whether our floor list, context menu and Alt cycling already provide sufficient visible guidance. A small chooser over existing hit candidates could be an interaction improvement if the audit proves the gap; it should not introduce new selection semantics or a general layer engine.
5. **Explain temporary state where it matters.** I: reveal active snap settings, selected object identity and reference lock status at the relevant interaction rather than adding a permanent row of technical controls. RoomSketcher documents both visible and keyboard snap routes, which supports offering a discoverable control without forcing shortcut memorization.
6. **Keep reference preparation recoverable.** I: make the current calibration stage and next action clear, preserve the known-distance explanation, and verify users can reopen or find the reference after drawing. Planner 5D's Find my image is a useful recovery pattern; inspect our existing Fit/reference controls before proposing another command.
7. **Preserve an escape and a way back.** I: keep current cancel/undo/conflict protections and make the applicable action understandable. Competitor Undo buttons establish familiarity, not permission to remove our write guards or imply all destructive actions are reversible.
8. **Constrain the interface before constraining the task.** I: test existing Details/Layers rails with actual drafts and selections. Competitor tablet support cannot validate a narrow Obsidian split pane. Keep drawing and confirmation controls visible, and retain the user's accepted edge-hover rotation preference with its existing numeric route.

## Capability traps excluded

This increment should not pursue 3D previews, renders, AI blueprint recognition, automatic furnishing, new libraries, CAD import/export, additional geometry primitives, new snapping algorithms, multi-floor management, field scanning or cost-estimation features. These may appear in competitor navigation but do not address the usability of existing 2D editing. Similarly, do not simplify away Existing versus Planned, wall impact review, reference locking or guarded history just to mimic another product's shorter flow.

The September 1 [research baseline](../../renovation-planner-editor-specs/Renovation%20Planner%20%E2%80%94%20Editor%20UX%20Research%20%26%20Pattern%20Study.md) remains useful for product direction, but its implementation inventory predates the current guide. The September 8 [rotation study](../../renovation-planner-editor-specs/implementation/rotation-ux-research.md) records a later user preference for small edge arrows on hover. A permanent Rotate label should not be reintroduced as an unquestioned competitive best practice.

## Confidence and validation limits

- **High confidence in what documentation says:** exact dimensional entry, reference calibration and alternate input routes recur across multiple independent vendors.
- **Moderate confidence in current runtime equivalence:** Floorplanner's current support page links an April 2025 manual, and Sweet Home 3D's guide names version 7.5. Documentation can lag products or differ by platform/tier.
- **Low confidence in comparative ease:** no observed completion rates, error rates, target sizes, keyboard traversal, focus behavior, screen-reader output, compact layouts or live account restrictions were measured.
- Marketing words such as easy, accessible and optimized are vendor positioning, not accessibility or novice-success evidence. For example, [Floorplanner personal-use positioning](https://floorplanner.com/personal) claims a non-overwhelming interface and precise input; this memo relies on its manual for interaction details.
- Some Planner 5D pages depend on diagrams/video that the extracted text does not fully describe. Exact icon functions and placement beyond explicit prose are not asserted. A Sweet Home 3D mobile-guide link redirected to unrelated staircase content during retrieval; it was excluded from mobile conclusions.
- Our product-side baseline comes from the current user guide and prior research, not an independent runtime or source-code verification in this memo. The main audit must establish whether each proposed usability gap exists.

Validation should ask a first-time user to choose a starting route, create a room, set a known size, reach an overlapping item, place an opening, recover a cancelled edit and reopen reference settings. Record unaided completion, first action, wrong-tool activations, backtracking and recovery success. Compare the current interface with a bounded proposed variant using the same supported tasks. No numerical improvement target is justified by these competitor sources alone.
