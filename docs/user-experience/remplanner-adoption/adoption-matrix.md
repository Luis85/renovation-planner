## Priority rationale

R01 follows an explicit user need and a confirmed gap, so it leads the implementation wave. R02 is small and makes existing power discoverable. R03 is useful but must be narrowly worded because active dimensions are editing controls, not decoration. R04 integrates these with the wall/color work. Everything else is retained, deferred behind a contract, or rejected. No paid-feature parity target or feature-count goal is adopted.
